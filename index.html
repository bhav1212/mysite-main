Project conceptAgent evaluation

Glassbox Agent Reliability Lab

A workbench that asks whether an agent completed the task—not just whether its final answer sounded right. Replay tool calls, inspect state changes, and compare reliable completion across repeated runs.

Why it fitsBuilds on my research in transparent multi-agent systems and my focus on LLM evaluation.

  • Tool-call replay and state diffs
  • Repeated-run reliability checks
  • Prompt-injection test scenarios
  • Cost, latency, and failure traces
First build

Start with a synthetic logistics booking workflow, a sandbox database, and a small frozen task set. Compare a single agent with a verifier-assisted workflow.

Proposed stack

Python · SQLite · pytest · OpenTelemetry · Interactive web UI

How to evaluate

Compare final database state with the expected result; report repeated-run task success, policy violations, attack success, latency, and cost separately.

02
Project conceptEvidence-first foresight

Signal Ledger

A technology-scouting workspace where every trend claim has an evidence trail. Connect research signals, expose contradictory findings, and show how a conclusion changes when evidence is added or removed.

Why it fitsExtends my technology-readiness and bibliometric research with a sharper focus on evidence quality.

  • Claim-to-source evidence graph
  • Supporting and conflicting findings
  • Evidence freshness and provenance
  • Human review before briefing export
First build

Use a frozen, openly available corpus for one technology area. Build a claim ledger and source-backed briefing, then evaluate on questions held out before tuning.

Proposed stack

Python · OpenAlex · PostgreSQL · GraphRAG baseline · Interactive web UI

How to evaluate

Compare graph retrieval with keyword and vector baselines using citation validity, evidence coverage, contradiction recall, reviewer usefulness, and cost. Research momentum is not a validated technology-readiness score.

Research sourcesOpenAlex documentationGraphRAG methods
03
Project conceptAI product & project management

AI Product Decision Lab

A product-discovery workspace that turns an AI feature idea into a testable decision: a user task, a simple baseline, a cost and latency budget, and evidence for a release or a stop.

Why it fitsConnects my AI product learning with my writing on discovery, evaluation, and the work around a demo.

  • Task and assumption mapping
  • Baseline versus AI comparison
  • Quality, cost, and latency gates
  • Human review and release decisions
First build

Build one synthetic research-briefing use case. Compare manual/search and retrieval-assisted workflows, document failure modes, and generate a release brief with explicit go, revise, or stop criteria.

Proposed stack

Python · FastAPI · PostgreSQL · LLM evaluation · Interactive web UI

How to evaluate

Compare decisions against a reviewed rubric on fixed product scenarios. Measure evidence coverage, task quality, cost, latency, and reviewer agreement. A readiness checklist is decision support, not proof that a product will succeed.
